# QA Test Plan — ONOVA Package Builder

## Scope

Функціональність конструктору фітнес-пакету:

- вибір тривалості перебування;
- вибір проживання, харчування й інтенсивності тренувань;
- вибір додаткових послуг;
- знижка за попереднє бронювання;
- миттєвий попередній перегляд;
- фінальний підсумок і скидання параметрів.

## Formula

```text
проживання = ціна проживання за день × дні
харчування = ціна харчування за день × дні
тренування = ціна тренувань за день × дні
додаткові послуги = сума обраних checkbox-послуг
знижка = round((проживання + харчування + тренування + додаткові послуги) × 0.10)
загальна сума = проміжна сума − знижка
```

## Console Error Analysis

Під час перевірки Console доцільно фіксувати:

- тип помилки: `RuntimeError`, `ReferenceError`, `SyntaxError`, `RangeError`, `Uncaught` або `NaN`;
- рядок і файл зі Stack Trace;
- дію користувача, яка спричинила помилку;
- стан DOM до і після помилки;
- очікуваний і фактичний результат.

Перевірена помилка для віджета:

- дію: введено `-5`, потім натиснуто скидання;
- очікувана поведінка: показано помилку валідації, поле й підсумок повертаються до початкових значень;
- фактична поведінка: помилка показана, після скидання 5 днів і 11 000 грн;
- висновок: помилка валідації оброблена правильно, `NaN`, типові помилки JavaScript і помилки DOM не з’явились.

Зовнішні попередження Console не пов’язані з логікою конструктору:

- порада щодо використання Tailwind CDN у production;
- обмеження Permissions Policy для `compute-pressure`;
- попередження Swiper про недостатню кількість слайдів;
- повідомлення вбудованого YouTube-плеєра та його запитів.

## Defensive Programming Audit

Рівень 1 — HTML захист:

- поле тривалості має `type="number"`, `min="3"`, `max="7"`, `step="1"` і `required`;
- помилка пов’язана з полем через `aria-describedby`;
- поле та кнопка мають стан перевірки через `aria-invalid` і `disabled`.

Рівень 2 — перевірка JavaScript:

- порожнє значення перетворюється на `NaN` і відхиляється;
- дробове значення відхиляється через перевірку `Number.isInteger`;
- від’ємні значення та значення поза межами відхиляються;
- для тарифів перевіряються `Number.isFinite` і дозволений список значень;
- проміжні й кінцеві суми перевіряються на `NaN` та `Infinity`.

Рівень 3 — захист відображення:

- усі текстові дані відображаються через `textContent`;
- небезпечні HTML-вставки (`innerHTML`, `insertAdjacentHTML`, `document.write`) не використовуються;
- перед запуском перевіряється наявність усіх ключових DOM-елементів;
- помилка налаштування не запускає розрахунок і записується в Console.

Результати перевірки:

| Сценарій | Результат |
|---|---|
| Порожнє поле | Pass: помилка показана, розрахунок заблоковано |
| `-5` | Pass: позамежове значення відхилено |
| `999999999999999` | Pass: надмірне значення відхилено |
| `2.5` | Pass: дробове значення відхилено |
| Коректне `5` | Pass: показано 11 000 грн |
| Скидання | Pass: відновлено 5 днів і 11 000 грн |

## Final Integration Audit

Перевірено у Chrome:

| Ширина viewport | Результат |
|---|---|
| 320 px | Конструктор відображається; поле, кнопки та підсумок не виходять за межі блоку |
| 375 px | Без горизонтального переповнення сторінки |
| 768 px | Форма і підсумок відображаються в адаптивній композиції |
| 1024 px | Двоколонкова композиція не перекривається |
| 1280 px | Сайт і конструктор відображаються у контейнері |
| 1440 px | Максимальна ширина контейнера дотримана |

Мобільна перевірка на 375 px:

- тривалість 7 днів;
- висока інтенсивність тренувань;
- знижка 10%;
- фактична сума: 17 640 грн;
- скидання: 5 днів, 11 000 грн.

Перевірка сумісності:

- форма працює через `input`, `change` та `submit`;
- `number`, `range`, `select`, `radio` і `checkbox` не конфліктують;
- блок підсумку оновлюється без перезавантаження сторінки;
- помилок JavaScript у логіці конструктору не виявлено;
- сторонні попередження Tailwind CDN, Swiper і YouTube не впливають на роботу віджета.
